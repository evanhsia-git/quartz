# Telegram 訊息截斷問題排除指南

本頁面記錄 Telegram API 訊息截斷（Truncation）的成因及其自動化防護機制。

## 1. 成因分析
訊息截斷通常由 Telegram 伺服器協議限制引起：
- **字元數限制**：單則訊息上限為 **4,096 個字元**（含 Markdown/HTML 標籤，標籤亦佔用空間）。
- **請求限制 (Payload)**：若單次 API 請求體過大（如嵌入 Base64 數據或過量文字），請求會被直接拒絕。
- **頻率與合併限制**：同時傳送多媒體附檔與長文字時，因 Telegram Bot Rate Limits 導致的發送異常。

## 2. 自動化防護規範 (2026-06-03 更新)

為了確保長篇金融報告與新聞推送的完整性，系統已建立以下標準操作程序：

### A. 長度監控與分段 (Pagination)
- **觸發條件**：當訊息預估長度超過 **3,500 字元**，系統強制啟動分段機制。
- **處理邏輯**：
    - 將報告內容依據語意邏輯（通常在第 5 條內容後）拆分為兩則訊息。
    - **編號標記**：第一則訊息結尾強制加上「(1/2) 接續下則」，確保閱讀流暢。
    - **執行順序**：兩則訊息連續發送，確保在聊天室中上下相鄰。

### B. 極簡格式化 (Minimalist Reporting)
- 為節省字元空間，新聞推送強制執行「標題 + 摘要」的極簡模式。
- **連結規範**：強制將連結隱藏在 Markdown 連結 `[連結](URL)` 中。
- **分行機制**：確保每則項目之間強制分行，並嚴格控制輸出字元以防止誤觸截斷上限。

### C. 檔案化交付 (File-based Delivery)
- 若報告長度超出兩則訊息的處理範圍（或需傳送數據表），系統自動轉為使用 `telegram-message-file-sender` 技能，將報告打包為 `.md` 或 `.pdf` 傳送。
- **嚴禁事項**：禁止使用 `send_message` 的 `MEDIA` 參數（經實測不穩定）。
