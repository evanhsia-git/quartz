## 0. 三個判準

> 每個功能都要能通過以下三個問題，任一題答「否」就降級為延後或刪除。

| 判準 | 問題 | 不通過的處理 |
|------|------|-------------|
| **執行效率** | 這個功能需不需要對全市場（~1700 檔）逐檔額外計算，或呼叫超出既有 Provider 呼叫量？ | 砍除，或合併進既有 Build 流程的既有欄位，不新開 job |
| **系統維護** | 這個功能需不需要新的 JSON 契約 / 新的 Provider / 新的 Optional 開關？ | 每多一份契約＝多一份要長期維護的東西；非核心一律不新增，能塞進既有 JSON 就塞 |
| **新手心態** | 這個功能會不會誘發追高殺低、過度交易、資訊過載，或讓新手誤以為是投資建議？ | 砍除，或改用「預設隱藏、進階模式才顯示」+ 加風險提示的方式保留 |

**優先順序**：三個判準衝突時，**新手心態 > 系統維護 > 執行效率**——這是一個公開给新手 fork 使用的平台，寧可少做也不要做出誤導新手的功能。

## 1. 核心模組：15+ 砍到 8 個

> v2.0 原本有 15 個模組（6.1-6.15）+ A-V 22 個功能分類，對一個 Fork 即用的新手平台而言範圍過大。以下合併/砍除後只留 **8 個核心模組**，其餘全部併入或延後（見第 7 節）。

| # | 簡化後模組 | 內容（取自原模組） | 為何保留 |
|---|-----------|---------------------|---------|
| 1 | **首頁** | Dashboard 精簡版：Watchlist + 資料新鮮度提示 + 風險警示彙整 | 新手第一眼要看到「這是什麼、資料多新、有沒有風險」，不是花俏卡片 |
| 2 | **大盤總覽** | 指數 K 線 + 漲跌家數 + 三大法人（合併原 B Market） | 理解大環境是投資的第一課，計算成本低 |
| 3 | **個股頁** | 價量 + 財報成長燈號 + 風險警示燈 + 個股新聞流（合併原 C + 部分 I News） | 新手最常用的單頁，資訊密度控制在「看得懂」範圍 |
| 4 | **ETF 專區** | 清單/篩選 + 折溢價 + 除息月曆 + 主動式 ETF 標註（合併原 D） | 台灣新手常從 ETF 入門，定期定額也多半用 ETF |
| 5 | **投資組合** | 持倉輸入 + 定期定額試算器 + 持倉集中度警示 + 基本績效（合併原 E） | 這是唯一直接影響新手實際決策品質的模組，優先做好而非做多 |
| 6 | **選股 & 排行** | 預設篩選模板為主、自由篩選為輔 + 排行榜改「長期導向」呈現（合併原 P Ranking + R Screener） | 見第 3 節「排行榜重新設計」——避免變成追高工具 |
| 7 | **策略與回測（簡化版）** | 少量預設策略 + 基本回測績效卡，不做因子中性化/Walk-Forward/策略疊加（合併原 F+G+H） | 量化功能保留「看得懂結果」的部分，砍掉研究級複雜度 |
| 8 | **新手學習中心** | 財報名詞辭典 + 除權息/財報行事曆 + 「如果當初買了」試算器 + 風險教育卡（合併原 J+L+M+N+U） | 用一個模組取代原本 5 個百科/日曆分類，教育內容集中管理，維護成本大降 |

**明確不進入 v3 核心的原模組**：K Market Replay、O Market Snapshot、S Compare（先不做，或合併進個股頁的「加入比較」小功能）、T Report Center、6.13-15 Optional 後端模組（Chat/Task/Settings 全部延後，見第 7 節）。

## 2. Z100 精選：100 砍到 18

> 判準：三個問題全過、且不需要新 Provider/新排程的才留。以下 18 項為 v3 建議實作，其餘 82 項全部歸入第 7 節「延後/刪除」，不逐條複述（原始 100 項清單見 v2.0 第 8 節）。

| 原編號 | 功能 | 歸入模組 | 保留理由（對應判準） |
|--------|------|---------|----------------------|
| #8 | 部署狀態徽章 | 首頁 | 零成本、維護透明度必要 |
| #9 | 資料新鮮度提示條 | 首頁 | 同上，且是「這不是即時盤中資料」的關鍵防呆 |
| #22 | 財報成長趨勢燈號 | 個股頁 | 用燈號取代大量數字，降低新手認知負擔 |
| #30 | 個股風險警示燈 | 個股頁 | 新手心態核心功能，防呆優先 |
| #46 | 持倉集中度警示 | 投資組合 | 直接對應「分散風險」教育目標 |
| #47 | 定期定額試算器 | 投資組合 | 新手最需要的行為工具，鼓勵長期紀律而非擇時 |
| #77 | 除權息倒數提醒卡 | 學習中心 | 教育型、零額外運算成本（既有資料衍生） |
| #76 | 財經日曆訂閱（.ics） | 學習中心 | 一次性產出，維護成本低 |
| #95 | 「如果當初買了」歷史試算器 | 學習中心 | 用真實歷史取代「猜明天」，訓練長期思維而非投機心態 |
| #71 | 規則式情緒燈號（非 AI） | 個股頁 | 不需要 LLM Key，零額外依賴 |
| #29 | 除權息填權速度追蹤 | ETF/個股頁 | 沿用既有除權息資料，成本低 |
| #35 | 高股息 ETF 除息月曆 | ETF 專區 | 同上，新手高股息 ETF 需求高 |
| #31 | ETF 折溢價追蹤 | ETF 專區 | 防呆功能：避免新手用市價誤判淨值 |
| #36 | ETF 費用長期侵蝕試算 | ETF 專區 | 教育型，用複利試算讓新手理解費用重要性 |
| #58 | 回測結果版本快照 | 策略與回測 | 維護面必要（見第 5 節），不是加值而是防止結果失真 |
| #81 | Issue Template：策略提案 | GitHub 治理 | 零開發成本，直接用 GitHub 原生功能 |
| #83 | Projects 看板：Roadmap 透明 | GitHub 治理 | 同上 |
| #100 | P1-P8 自我體檢報告 | GitHub 治理 | 系統維護核心：自動守住紅線比人工複查可靠 |

**特別排除說明**：原本被列為「必做」的 #14（台版恐慌貪婪指數）、#53（Walk-Forward）、#65（因子權重優化）在 v3 明確降級或刪除——這些對新手沒有直接行為指引價值，且計算/維護成本偏高，留給未來「進階模式」若有需求再開。

## 3. 新手投資者心態設計準則

> 這節是本次簡化的核心，不只是砍功能，而是**重新設計呈現方式**，讓平台預設狀態不會誘發新手常見的行為偏誤。

| 設計準則 | 具體規則 | 對應被修改/砍除的功能 |
|---------|---------|------------------------|
| **不做即時盤中資訊** | 全站只呈現前日收盤資料，且首頁明顯標示「非即時」 | 排除任何即時 Tick、期現貨即時價差類功能 |
| **排行榜不強調短期漲跌** | 「漲跌幅排行」預設改為顯示「近 1 年」而非「當日」；當日排行需手動切換並附「短期漲跌不代表投資價值」提示 | 原 Z2/#11、Ranking 模組的預設排序邏輯調整 |
| **不做競賽/排行榜式的交易遊戲** | 模擬交易競賽、Contributor 排行榜等「比較誰厲害」的機制一律不做，避免鼓勵冒險行為 | 原 Z10/#91、Z9/#85 直接刪除，非延後 |
| **量化研究功能預設收合** | 因子中性化、Walk-Forward、策略疊加等研究級功能全部歸類「進階模式」，預設不顯示在新手會看到的路徑 | 見第 1 節模組 7 的範圍限縮 |
| **AI／合理價類功能不做預設** | 任何「自動算合理價」「AI 摘要建議」類功能一律標示為輔助資訊、非投資建議，且預設關閉（需自行設 Optional Key 才出現） | 原 Z3/#21、Z8/#72/#74 全部維持 Optional，且加強免責聲明要求 |
| **槓桿/衍生品類功能不做首屏** | 反向/槓桿 ETF、期貨相關功能若做，一律附教育型風險說明卡，且不進入預設導覽選單 | 原 Z2/#17/#20、Z4/#37 全部延後 |
| **教育內容優先於進階分析工具** | 學習中心（模組 8）在導覽順序中排在選股/回測之前，引導新手先理解基礎再用工具 | 導覽順序調整，非功能刪減 |
| **每個排行/篩選結果附「這不是建議」提示** | UI 層級規則，非單一功能，所有排序類頁面統一 footer 提示 | 適用於選股 & 排行、個股頁 |

## 4. 執行效率具體措施

| 措施 | 說明 |
|------|------|
| 模組從 15+ 砍到 8 個 | JSON 契約數量同比例減少，Build Time pipeline 步驟數下降 |
| 學習中心內容為靜態資料 | 財報辭典/教學頁不需要每日重算，只需版本化更新，不占用每日排程時間 |
| 排行榜複用既有因子/價格資料 | 不新增計算，只改變預設排序欄位（近 1 年 vs 當日） |
| 回測範圍縮小 | 不做 Walk-Forward、蒙地卡羅打亂測試等高運算量分析，避免 Actions job 時長暴增 |
| Compare/Market Replay 延後 | 這兩者運算量相對高（歷史逐日重建、多標的即時比較）但新手使用頻率低，優先犧牲 |

## 5. 系統維護具體措施

| 措施 | 說明 |
|------|------|
| 8 個模組 = 8 份 Data Contract | 相較 v2.0 15+ 模組，schema 斷版風險同比例下降 |
| 學習中心合併 5 個原分類 | 原本 J/L/M/N/U 五個獨立分類會產生 5 份契約，合併後只需 1 份，內容用同一 JSON 的不同 section 呈現 |
| 回測結果版本快照（#58）列為必做 | 防止策略程式碼更新後，舊回測結果被覆蓋而失去可信度——這是維護性問題，不是功能加值 |
| P1-P8 自我體檢報告（#100）列為必做 | 用自動化取代人工複查，是所有簡化決策長期不失守的保險機制 |
| Optional 後端模組全數延後 | Chat/Task/Settings 三個模組需要 Hermes 常駐服務，對「Fork 即用」新手平台而言維護成本與受眾不成比例，v3 不列入任何 Phase，待社群明確需求再議 |

## 6. 簡化後 Phase Roadmap

> 相較 v2.0 的 4 個 Phase，v3 只分兩階段——新手平台不需要「Enterprise」層級。

| Phase | 範圍 | 目標 |
|-------|------|------|
| **Phase 1（核心）** | 8 個核心模組全部上線，含第 2 節 18 個精選功能 | 一個對新手友善、Fork 即可用、零額外維護負擔的完整平台 |
| **Phase 2（進階選配）** | 因子中性化、Walk-Forward、Compare、Market Replay、AI 摘要類（設 Key 才啟用） | 只在社群明確提出需求、且不影響 Phase 1 穩定性時才啟動，全部走 Optional 開關，預設不出現在新手導覽路徑 |

> 不再設 Phase 3/4：Optional 後端模組（Chat/Task/Settings）與百科全書系列（獨立 L/M/N）在 v3 判準下已被砍除或合併，沒有對應的後續 Phase 需要規劃。

## 7. 明確刪除/延後清單

> 對原 v2.0 藍圖的最終處置，供未來回頭查核「為什麼沒做」。

| 類別 | 項目 | 處置 | 理由 |
|------|------|------|------|
| 模組 | K Market Replay、O Market Snapshot、T Report Center | 刪除（不進 Phase 2） | 運算/維護成本相對高，新手使用場景弱 |
| 模組 | 6.13 Chat、6.14 Task、6.15 Settings | 刪除（不進任何 Phase） | 需要常駐後端，與 Fork First 精神衝突最大 |
| 模組 | S Compare | 延後至 Phase 2 | 非核心，可用個股頁的簡易比較取代 |
| Z100 | 除第 2 節 18 項外的其餘 82 項 | 延後至 Phase 2 或刪除 | 逐項判準見 v2.0 原表；凡涉及新 Provider、新排程、或高運算量者一律不進 Phase 1 |
| 心態相關 | 模擬交易競賽（#91）、Contributor 排行榜（#85） | 直接刪除，不延後 | 違反「不鼓勵競賽式冒險行為」準則，非成本問題 |
| 心態相關 | 恐慌貪婪指數（#14）、槓桿/反向 ETF 相關（#37）、期現貨價差（#17） | 延後且必須帶風險教育卡才可上線 | 對新手而言資訊超前於需求，容易造成誤用 |
